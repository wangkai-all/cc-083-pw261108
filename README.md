# 数据契约登记台（Data Contract Registry）

导入 **JSON Schema** 或 **Avro** 定义，按数据集维护版本，比较结构变化对现有生产者与消费者的兼容影响。零依赖、免构建，核心引擎有完整单元测试。

## 运行

```bash
npm start          # http://localhost:8000 （可传端口：node server.js 9000）
npm test           # node:test 引擎测试（39 个用例）
```

需要 Node.js >= 20（使用 Web Crypto 计算内容指纹）。数据保存在浏览器 `localStorage`，无需后端。

## 核心能力与规则落点

### 1. 按数据集维护版本
- 每个数据集下导入带版本号的定义；草稿可**发布**，发布版本构成可比较的历史契约链。
- 内容指纹为**解析后逻辑结构**规范化 JSON 的 SHA-256（键序、空白差异不影响同一性）。
- **同版本号 + 同内容**：幂等跳过；**同版本号 + 不同内容：拒绝覆盖**（`VersionConflictError`），杜绝同名版本被悄悄改写。
- **解析失败**：原始文件、文件名、错误与定位全部保留，状态标记为 `未评估`；不生成 IR、不能发布、不参与比较与任何“通过”结论。

### 2. 结构化变更分类（不是文本 diff）
两版本先解析为统一 IR 再按字段路径比较，每类变更分别给出三个方向的结论与原因：

| 检查方向 | 含义 |
| --- | --- |
| 旧生产者写新结构 | 旧数据能否被新结构读取（向后兼容） |
| 新生产者写旧结构 | 新数据能否被旧结构读取（向前兼容） |
| 消费者读取 | 消费侧两方向综合风险 |

重点变更的兼容方向（结论分 `通过 / 有条件通过 / 不通过 / 未评估`）：

- **新增可选字段**：向后通过；向前取决于读取器是否忽略未知字段（有条件）。
- **删除必填字段**：向前不通过（新生产者不再产出，旧结构必填校验失败）；向后取决于未知字段策略。
- **收窄类型**：向后不通过（旧宽值可能截断/失败）；**放宽类型**方向相反。Avro `int`/`long` 视为同宽，数值按 `int=long < float < double` 判定。
- **枚举加值**：向前不通过（旧读取器不认识新符号）；**枚举删值**向后不通过（历史数据重放失败）。
- 另有：新增必填（带/不带默认值分开）、删除可选、必填↔可选、可空↔非空、默认值变更、类型族变化、union/fixed 变化。

### 3. 可选、可空、默认值严格区分
三者是正交概念，在 IR 与 UI 上分别用独立标记表示，比较时分别产生独立变更，绝不混为一类：
- `required`（结构上是否必填）、`nullable`（是否接受 `null`）、`hasDefault/default`（缺失时是否有填充值）。

### 4. 改名与别名
- 识别 Avro `aliases` 与 JSON Schema 厂商关键字 `x-aliases`。
- 有别名但**未用旧样例验证**时，消费者方向判为不通过，不能给出整体通过结论。
- 在比较页粘贴**按旧结构写出的样例数据**执行验证：新结构经别名映射成功读取旧字段后，结论升级为“别名已验证”；验证失败会定位具体字段。
- 无别名的一对一改名识别为 `renamed-no-alias`，双向不通过。

### 5. 样例数据校验
- 坏样例错误定位到嵌套字段路径，如 `items.[1].qty`、`order.items.[0].sku`。
- 覆盖必填缺失、枚举非法、类型不符（含 int 范围）、null 给非空字段、`additionalProperties=false` 下的未知字段、union 成员匹配、fixed 字节长度。
- 版本详情页可一键生成样例骨架。

### 6. 详情、结论与报告导出
- 版本详情：统一 IR 契约树（含可选/可空/默认值/别名标记）、解析失败留存的原文件、原始定义导出。
- 比较页：三方向汇总徽章 + 每条变更的三方向结论卡片。
- 报告：导出 JSON（机器可读）与 Markdown（含版本指纹、三方向结论表、逐条语义说明）；未评估比较产出单独的“未评估”报告。

## 目录结构

```
src/core/            纯逻辑引擎（浏览器/Node 通用，可独立复用）
  parseJsonSchema.js JSON Schema -> IR（含本地 $ref、x-aliases）
  parseAvro.js       Avro -> IR（union/命名类型/aliases/logicalType）
  schemaCompare.js   结构化变更分类 + 三方向兼容规则
  validate.js        样例校验与别名旧数据可读性验证
  registry.js        登记/版本/冲突拒绝/未评估留存/发布/比较编排
  report.js          JSON / Markdown 报告
  storage.js         localStorage 与内存存储（测试用）
src/ui/              零框架 ESM 界面（hyperscript + hash 路由）
tests/               node:test 用例与夹具
server.js            零依赖静态服务器
```

## 快速体验

打开页面后，在浏览器控制台执行：

```js
const { datasetId, v1, v2 } = await import('/src/ui/seed.js').then(m => m.seedDemo());
```

即得到一个含两个已发布版本和一个未评估版本的演示数据集。

## 已知边界

- JSON Schema 支持 Draft-07 风格常用子集；外部 `$ref`、`oneOf/anyOf/allOf` 组合器未实现（本地 `$ref` 含递归引用已支持）。
- Avro `logicalType` 仅作元信息保留，不参与兼容判定。
- 无别名的改名采用“一对一增删且类型骨架相同”的启发式识别；多字段同时改名且无别名时按新增/删除分别报告。
